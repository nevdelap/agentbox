Open release regression

C-1 — Major — lifecycle lock spans interactive execution.

Status: Confirmed open; Task 17 is specified but implementation is still pending.

Evidence: bin/ab states that the project-lock descriptor is inherited by docker exec and intentionally remains open through the final report (bin/ab:655–658). policy_operation_begin acquires that lock (bin/ab:3596–3602), while the public bash, claude, codex, and explicit exec paths call cmd_exec and only end the report guard after Docker returns (bin/ab:4497–4526 and bin/ab:4629–4660). There is no lock release before the long-lived child session.

Impact: A second command for the same project cannot acquire the lock while the first interactive session is alive, waits the 30-second timeout, and reports a false project busy failure. This regresses the previous ability for multiple agents to enter the same project concurrently.

Required task boundary: serialize policy/lifecycle inspection and mutation, release the project lock before long-lived interactive execution, and preserve the mutation guards and state revalidation needed around the handoff. Add a real multi-process/concurrent session test; the current Task 10 tests only assert single-process/reentrant acquisition and mock cmd_exec (tests/run.sh:4180–4214).

Current reproduction: The reported rebuild-then-two-entry attempt is consistent with the current source. The working-copy diff contains only the Task 17 Markdown specification and this review document; bin/ab, the lifecycle library, and the executable test implementation are unchanged. Therefore no lock release has been delivered yet.
