Scope for this reset

Tasks 8–11 are scoped to making the existing agentbox tool safe and usable during development: reconcile configuration and policy changes explicitly, expose enough state to explain what happened, provide dependable command outcomes and diagnostics, coordinate lightweight update checks, and handle the nested runtime’s readiness and replacement path where the current tool needs it.

The original definitions of Tasks 8–11 fit within that boundary. They are appropriate feature work for this tool, not an over-engineered platform design, provided their implementation remains local to the existing launcher, container lifecycle, locks, volumes, and command surface.

This scope is intentionally local to one host, one project, and the existing container/volume lifecycle. It does not define a public API, a distributed coordination system, a general-purpose workflow engine, or an exhaustive event/history model. It does not require new policy capabilities beyond those already described by the plan. Features that do not support the core lifecycle or make failures diagnosable should remain out of scope for this group.

The implementation should favor the smallest behavior that satisfies the listed acceptance cases. Stable user-visible outcomes and no-surprise safety behavior matter; internal representation, byte-level wire compatibility, and elaborate provenance matter only where an existing command or test genuinely depends on them.
